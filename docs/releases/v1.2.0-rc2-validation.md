# BDR v1.2.0-rc2 validation record

Status: release-candidate freeze validation

## Baseline and scope

- Frozen RC1 baseline: `eb77ad7286f234243ca1ed1a2af2d55df8c12238`
- RC2 branch: `release/v1.2.0-rc2`
- Defect reproduced in RC1: a multi-operation atomic batch using `PerOperationSync` was rejected by V110 and surfaced through Atomic C ABI v2 as I/O error.
- Required invariant: one logical batch = one sequence = all-or-nothing visibility/recovery.

## RC2 contract

`write_batch` remains one atomic visibility and sequence boundary. `PerOperationSync` accepts multi-operation batches and never splits a logical batch into independently visible or recoverable commits. With the current BDW4 writer, synchronous durability modes persist one framed batch and synchronize before returning.

## Freeze rule

No new features belong in v1.2.0-rc2 after this validation point. Only release-engineering corrections (metadata, documentation, CI/release packaging) should be accepted before the immutable tag is created. Any storage-semantic change requires a new candidate and a complete rerun of the validation gates.
