# V0.3 Compact Index Ablation

## Objective

Measure whether replacing per-slot `std::string` key/value storage with compact slot metadata plus a contiguous arena reduces memory usage without regressing insertion/lookup behavior in an insert-only microbenchmark.

## Result

All scenarios used 1,000,000 records and verified 10,000 deterministic lookups.

| Value bytes | Baseline RSS KiB | Compact RSS KiB | RSS reduction | Baseline time s | Compact time s |
|---:|---:|---:|---:|---:|---:|
| 0 | 184,716 | 88,448 | 52.1% | 0.404 | 0.340 |
| 16 | 213,416 | 114,252 | 46.5% | 0.673 | 0.293 |
| 128 | 316,492 | 265,252 | 16.2% | 0.789 | 0.544 |

The experiment therefore shows a real reduction in RSS, especially for small values, and did not show an insertion/lookup regression in this microbenchmark.

## Important limitation

The current compact prototype uses an append-only arena. Updating an existing key appends a new key/value representation and leaves the previous bytes unreachable. It also does not yet implement the full erase/compaction semantics required by the production index.

Therefore this result is **not sufficient to replace the V86 ResolutiveIndex**.

Before promotion, the compact design must pass a churn experiment with repeated updates/deletes and demonstrate bounded memory growth, correct reclamation/compaction, and no regression in existing concurrency/crash/recovery gates.

## Decision

Promising architecture candidate; not yet production candidate.
